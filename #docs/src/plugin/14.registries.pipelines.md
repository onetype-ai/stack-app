# Registries and pipelines

A **registry** is a named list of data one plugin declares and its dependants
fill through `adds`. `layout` declares one; `LayoutFrame` reads it with
`useRegistry("layout.links")`:

```ts
    registries: {
        "layout.links": { describe: "A shortcut in the frame, as data.", entry: LayoutLink.schema, key: "id" },
    },
```

A **pipeline** is ordered steps one plugin owns. A dependant adds a step
beside an anchor, `after: "tidy"`, through the same `adds`. `items` owns
one, and adds a link to `layout`'s registry:

```ts
    pipelines: {
        "items.create": {
            describe: "Turns a draft into a stored item.",
            input: ItemDraft.schema,
            output: Item.schema,
            steps: [
                { id: "tidy", run: (draft) => ItemDraft.tidy(draft) },
                { id: "store", run: (draft, ctx) => itemsApi.create(ctx, ItemDraft.tidy(draft).title) },
            ],
        },
    },

    adds: {
        "layout.links": [{ id: "items", label: "All items", to: "/items", order: 10 }],
    },
```

`ctx.pipeline("items.create").run({ title })` checks the input, runs each
step on the last one's answer, and checks the output. No step runs inside a
transaction. Every entry and step is checked at start, all at once. The rest,
with the refusals, is the kit's `#docs/procedures/registries-and-pipelines.md`.
