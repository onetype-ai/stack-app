# services/

One class a file, built once per plugin and handed `ctx`. It calls `api/`,
never the server, and parses nothing because the api already did.

```ts
import { itemsApi } from "../api/items";
import { ItemsKeys } from "../utils/ItemsKeys";

import type { Context } from "@onetype/stack-app-kit";
import type { Item } from "../types/Item";

export class ItemStore
{
    readonly #ctx: Context;

    constructor(ctx: Context)
    {
        this.#ctx = ctx;
    }

    list(): Promise<readonly Item[]>
    {
        return itemsApi.list(this.#ctx);
    }

    async create(title: string): Promise<Item>
    {
        const item = await itemsApi.create(this.#ctx, title);

        this.#ctx.cache.invalidate(ItemsKeys.list());
        this.#ctx.events.emit("items.created", { id: item.id });

        return item;
    }
}
```

A write drops the cache keys it changed, then emits. `utils/ItemsKeys` holds
every key, so a hook and a service cannot disagree.
